## Windows failure and smallest proposed correction

`tests/foundation.test.ts:16` expects running `ports-nonexistent-test-executable` to return `failure: "missing"`. The actual Windows result has `failure: undefined`. All other 50 tests passed, including environment inheritance, cancellation and the foreground-editor lifetime regression.

Source inspection explains the platform difference: installed Execa uses `cross-spawn._parse`, which routes an unresolved Windows command through `cmd.exe`, then spawns it with Node's native spawn. It does not use cross-spawn's `hookChildProcess` missing-command conversion. Consequently a shell command failure need not carry `code: "ENOENT"`, while `runCheckedCommand` recognizes missing executables only by that code. Do not weaken the test or classify every exit code 1 as missing: genuine command errors must stay command errors.

Proposed correction: narrowly establish executable-resolution failure on the Windows launch path and map only a proven missing executable to `missing`, preserving PATH/PATHEXT resolution, command arguments, launcher environment and normal nonzero statuses. Add assertions distinguishing a missing command from an existing executable returning 1, then rerun the complete matrix. Capture the Windows raw result during verification if needed to validate the mapping. No implementation correction was made in this verification stage; the requested failure response was investigation and a proposal. No dependencies or architecture were changed.
