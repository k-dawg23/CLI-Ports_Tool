### Native Linux checks and evidence

The native smoke script created a target server with IPv4/IPv6 listeners and a separate owned sentinel server. It refused to invoke port-based termination unless every discovered row on the target port belonged to its target child. Only test-owned child processes were signaled or cleaned up; unrelated processes were not terminated.

The four checks passed:

1. The owned target appeared in built CLI JSON, static table, and detailed check output.
2. Native `lsof` valid IPv4/IPv6, controlled no-match, and invalid-option signatures were captured and verified.
3. The CLI stopped the owned target successfully while the owned sentinel survived.
4. Successful discovery reported the released port free, removed the exited target, and continued reporting the sentinel.

Raw commands, stdout, stderr, exit statuses, and platform/tool details are recorded in [native-linux.json](native-linux.json). A separate stable copy of the captured `lsof` fixtures is retained in [the regression fixtures](../../tests/fixtures/linux-lsof.json), replayed on every test host.

Browser/editor launch behavior, including paths with spaces, was verified through command-runner stubs. No real browser or editor was launched. Shared-port and forced-escalation scenarios use fixtures/mock probes and signals; the real native stop check exercised normal termination of an owned child.

## Specification reconciliation and deviations

There are no additional product features or intentional scope departures. The following implementation choices and verification limitations are recorded explicitly:

| Item | Resolution |
| --- | --- |
| Native Linux no-match signature | This environment emits paired `can't stat() overlay/nsfs file system` / `Output information may be incomplete.` warnings with both successful listener queries and a controlled no-match exit 1. Section 7.3 explicitly permits a verified platform-specific classification. The implementation accepts only empty stdout/status 1 with those exact warning forms on Linux and retains a visibility warning. Extra/unknown diagnostics still fail; macOS does not inherit the Linux exception. |
| Small project module change | `getPackageContext` accepts an optional collection context and stages cache writes so late enrichment cannot publish. This is required deadline handling, not cache invalidation or a change to project/framework detection. |
| Windows query separation | Required listener enumeration is separated from optional batched process/CIM enrichment so a stalled enrichment query cannot lose already discovered listeners. No general performance redesign was added. |
| Unix liveness | Uses the kernel-backed Node `process.kill(pid, 0)` probe so numeric `ESRCH`/`EPERM` errors distinguish absence from permission outcomes. It sends no terminating signal. Other errors remain unknown. |
| Command test seam | Command handling was extracted into `src/commands.tsx`, leaving the executable entry point small. This permits proof that parsing/help/version do not create a backend, without production test switches or extra runtime dependencies. |
| Restricted-process environment | Initial restricted test execution and clean installation encountered `EPERM` while launching/capturing child processes. Both were rerun with the required process access and passed. This did not require a product-code workaround. |
| Native/CI verification | Windows/macOS and Node 22.18.0 were unavailable locally. Their checks remain pending; CI configuration is provided but was not dispatched or observed in this work. AC-12 is therefore pending. |

The original three-second refresh interval, Unix SIGTERM/conditional SIGKILL sequence, Windows Stop-Process/conditional forced-stop sequence, and successful JSON schema are retained. The authoritative specification's incomplete-stop and unknown-verification exceptions are implemented and documented as intentional compatibility corrections.
