- `npm test` — 10/12 test files passed. The two failing files exercise captured child-process output; a direct `runCheckedCommand` probe also returned empty stdout/stderr for a child that exited with status 7. The backend assertion failure seen in an earlier run was a test expectation ordering issue; it was corrected to preserve backend enumeration order, and all 15 focused backend tests then passed.
- Focused `tests/backends.test.ts`, `tests/cli.test.ts`, `tests/project-cache.test.ts`, `tests/readiness.test.ts`, `tests/version.test.ts`, and `tests/actions.test.ts` — passed. TUI tests also passed in the full suite.

- `npm run test:integration` — failed in the built-CLI integration test because its spawned CLI output was empty, causing JSON parsing and stream assertions to fail. This prevents local built-CLI verification; rerun in CI.
- `npm run test:native` — attempt 2 confirmed the environment rejects owned loopback binds with `EPERM` for IPv4 and IPv6. Evidence is retained at [native attempt 2](v2.0.2-linux-attempt-2-2026-11-07/native-linux.json). Attempt 1 is retained separately at [native attempt 1](v2.0.2-linux-attempt-1-2026-11-07/native-linux.json).

## Deviations and pending evidence

- Plain `npm ci` could not complete because the sandbox returned `EPERM` while its install hook invoked esbuild for binary validation. Dependencies were restored with `npm ci --ignore-scripts`; this is not counted as a successful `npm ci` acceptance check.
- Local network isolation denied both IPv4 and IPv6 listener binds. The native smoke harness now records attempted, available, and unavailable hosts; its failed attempt remains preserved. This is not evidence that either address family is unavailable on Ubuntu generally.
- The built-CLI integration and two child-process test files remain unverified locally because child output was empty under this execution environment. Their failures were retained; no artifacts were overwritten.
- No macOS or Windows check was run here. Their CI jobs and current artifacts remain pending, including native IPv6 availability, PowerShell version/discovery evidence, and ConPTY selected-row binding details.
- Implementation-order deviation: the `PortService` cwd TTL change was made while binding data was being propagated through the same enrichment/fallback path, before the list-filter work was complete. The requested component order was otherwise followed for the user-facing changes and focused verification; this did not introduce an architectural redesign.
- No application behavior deviations from the v2.0.2 specification are intentionally introduced. The implementation follows the requested change map without a broader architecture redesign.
