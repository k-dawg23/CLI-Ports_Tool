# Windows executable classification and CI artifact correction

Date: 2026-11-05.

## Evidence and correction

Run [42047022604](https://github.com/k-dawg23/CLI-Ports_Tool/actions/runs/42047022604), Windows job 127312649230, reproduces the missing-executable assertion failure at `tests/foundation.test.ts:16`: expected `missing`, received `undefined`; 50 other tests passed. Installed Execa parses unresolved Windows commands through cmd.exe but does not install cross-spawn's missing-command exit hook, so the resulting exit status lacks ENOENT.

`src/system.ts` now recognizes a Windows exit-1 result as missing only when filesystem checks establish that no candidate exists in the current directory or PATH, considering PATHEXT and exact filenames. Quoted PATH entries and explicit paths are supported. Any existing candidate or uncertain filesystem error prevents this additional classification. Execa still performs actual resolution, escaping and execution with the original command and arguments. ENOENT handling, Unix behavior, locale settings, timeouts, cancellation and launcher lifetime remain unchanged. No dependency or architecture changes were made.

Regression coverage distinguishes missing commands from an existing executable returning 1, 7 or 9009. A Windows-only test exercises CMD/BAT lookup through a quoted PATH entry containing spaces, PATHEXT, absolute and relative paths, current-directory lookup, argument preservation, and an existing cmd.exe whose child command fails. That shell failure remains an ordinary nonzero result.

The native script accepts an optional `PORTS_NATIVE_OUTPUT_DIR`, retaining its existing local default. CI creates a fresh directory under RUNNER_TEMP for the run/attempt and uploads only that directory. Upload is skipped if preparation was skipped. Previously checked-in historical evidence cannot enter these artifacts. Failed smoke execution can still upload the newly generated failure record.
