## 2. Stage 1 feasibility

### Approach and suitability

`pty.openpty()` creates the kernel master/slave pair. The Python helper sets 160 columns × 60 rows, creates a child in a new session and applies `TIOCSCTTY` to its slave stdin. The child's stdin, stdout and stderr are attached to that slave. The helper's own protocol pipes transport input/output to the controller; they are not substituted for the Node child's PTY.

The child reports its controlling foreground process group before exec, and the host records the child's session ID and slave path. Both matched the spawned child identity in the successful artifacts. This supplements Node's actual `stdin.isTTY`, `stdout.isTTY`, raw-mode and dimension observations.

Python documents Unix PTY support and warns about mixing macOS fork-based PTY work with higher-level system APIs. This helper is isolated and single-threaded; it uses low-level descriptor/terminal operations and immediately execs Node, with no networking or macOS higher-level framework calls in its pre-exec callback. [Python PTY documentation](https://docs.python.org/3/library/pty.html), [termios documentation](https://docs.python.org/3/library/termios.html).

### Actual outcomes

On Linux and macOS, the independent feasibility rerun and the final matrix each demonstrated:

1. Native `/dev/pts/0` (Linux) or `/dev/ttys000` (macOS), a new owned session, and a matching controlling foreground group.
2. Actual interactive stdin/stdout and available raw mode; 160×60 dimensions.
3. Raw mode enabled and individual `a`, Up Arrow (`ESC [ A`), `b` and `q` key events received through the PTY.
4. Captured original terminal output, followed by the probe's `raw:false` completion marker and normal child exit 0.
5. Reaped child and closed PTY/control descriptors.
6. Separate deliberate abort and controller-disconnect scenarios. Each interrupted the still-interactive probe, closed the owned terminal/control channel and reaped the child. The recorded exit was `-1` (SIGHUP), explicitly an expected failure-path cleanup result, not normal exit. These scenarios do not claim successful application raw-mode restoration or fully drained output after interruption.

Linux additionally passed an independent post-exit ECHO/ICANON termios comparison. On macOS, the session leader's exit invalidates subsequent slave terminal ioctls in these runs (`ENOTTY`); the record explicitly retains `terminalRestoredByChild:null` and the inspection limitation. macOS acceptance instead uses the actual successful raw-mode-off observation before normal child exit plus terminal destruction. It does not claim a successful post-exit termios comparison.

### Harness issues investigated

- An initial local attempt queried the terminal foreground group from the parent. That ioctl was moved into the child owning the controlling terminal.
- Initial CI macOS probe interaction and exit worked, but the post-exit termios query raised ENOTTY and interrupted the helper's explicit cleanup reporting. The narrow correction records the unsupported inspection and continues closing descriptors. That first result remains FAIL; it was not relabeled successful.
- During local Stage 2 development, waiting for an IPC fixture's later `close` event stalled after the process had actually exited. A standalone reproduction showed `exit:0` without the awaited close event in this local setup. The Unix scenario now uses the proven child `exit` event, as the existing native guard harness does, and explicitly destroys the stderr pipe. Unique project names also prevent separate diagnostic runs from matching each other's search rows. Stalled diagnostic controllers were interrupted through their own execution sessions; their fixtures exited through owned IPC disconnect. A subsequent read-only check found none of those specifically named diagnostic listeners still running. No unrelated process or broad process-name kill was used.

These were infrastructure issues. They were corrected before successful Stage 2 CI execution; no approved application behavior changed.

## 7. Evidence assessment

Evidence is retained locally under `docs/verification/unix-pty-experiment/`, including initial/corrected feasibility artifacts, final full job logs, run/job results, artifact metadata/digests, raw terminal transcripts, decoded checkpoint frames, native observations, launcher logs, native smoke records and an implementation snapshot. `local-stage2/` retains the successful local worktree precursor, not a claimed CI-tested commit. Its missing GitHub run/SHA fields are not fabricated; final CI records provide exact candidate provenance.

The native parts are kernel PTY allocation, controlling-terminal ownership, real Node/Ink raw mode and keyboard input, compiled CLI rendering, production lsof/ps discovery and cwd lookup, actual automatic timers, target validation and child exits. The loopback listeners are real owned processes. The editor is a real harmless child executable. Browser execution alone is intentionally intercepted, as permitted by section 7.3.

The decoder reads captured terminal output; it does not provide the terminal to the application. It applies cursor movement and clearing before current-screen assertions, retains the original raw bytes/text, and rejects unsupported complete cursor/control sequences rather than treating historical text as the current screen. It is a small evidence decoder, not a full terminal emulator.

The refreshed native smoke captures also passed: Linux lsof 4.99.4 and macOS lsof 4.91, native IPv4/IPv6 listeners, controlled no-match with empty output/status 1, and invalid-option diagnostics/status 1. No new empty-result classification was introduced. Existing Linux warning regression evidence remains intact.

## 8. Remaining limitations

- Fixed 160×60 terminal sessions and a limited single-width-character decoder; resize, complex Unicode display widths, mouse, paste and other emulator features are not qualified.
- Hosted Linux x64 and macOS arm64 images only; no claim for every OS version, CPU architecture or terminal emulator.
- macOS post-exit termios inspection is unavailable in these runs; actual raw-mode restoration and terminal closure are evidenced separately.
- The abort/disconnect paths were deliberately exercised and reaped. Arbitrary kernel hangs or every possible host crash were not fault-injected; no unsafe PID-signal fallback exists.
- Real GUI application associations and graphical editor/browser behavior were not tested. Harmless launchers satisfy the requested shortcut boundary.
- No physical Mac was used. No human desktop-terminal visual review was performed on Ubuntu Studio or macOS. Functional Linux checks were performed in a real local PTY and in CI; those are automated observations, not a human presentation sign-off.
- The local system reports Ubuntu 24.04.5 LTS, Python 3.12.3 and Node 24.21.0. Local feasibility, corrected Stage 2, 54 regression tests plus one Windows-only skip, type checking, build and all three built integration tests passed. Successful strict-decoder replay covered both the local Unix transcript and retained Windows transcript. Local diagnostic failures remain distinguished from final passing CI.
- Repeated-run reliability across changing runner images has not been established. Current passing runs demonstrate feasibility and this application's functional requirements, not a broad reliability guarantee.

## 9. Reusability assessment

The approach is suitable for future Unix CLI verification on Linux/macOS CI without physical-machine access. The Python host, private lifetime channel, keyboard feasibility probe, stage gate and evidence protocol can be reused with application-specific scenarios. Keep the helper single-threaded and isolated on macOS, and preserve the explicit cleanup/termios limitations.

Reasonable shared leaf components are the harmless keyboard probe, authenticated listener guard/fixture and limited transcript decoder. Those existing components were reused directly; no general-purpose framework or unnecessary Windows/Unix host abstraction was introduced. The Unix host uses standard POSIX terminal operations, while Windows retains its native ConPTY/job-object implementation. Future reuse should independently qualify required escape sequences, terminal dimensions, timeout budgets and failure behavior.
