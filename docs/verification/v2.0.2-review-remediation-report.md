# v2.0.2 review remediation

Local remediation on 2026-11-07. No commit, push, tag, or release was made.

## Findings and corrections

1. **Windows integration expectations:** The fixture emits loopback on Windows and wildcard on Unix, while the assertion expected wildcard everywhere. In Windows metadata-error mode, the fixture also cannot derive a project name. The assertions now account for both differences.
2. **Known Windows PID replacement:** Windows detected a changed start time locally, but the service cache did not receive that invalidation. The backend now exposes collection-scoped invalidated PIDs; the service excludes them from enrichment and deadline fallback and stages cache invalidation for publication. An unavailable cwd is not cached as a successful acquisition. Tests cover failed CIM refresh, recovery, and deadline fallback with addresses retained.
3. **Malformed IPv6 scopes:** Both parsers validated only the substring preceding `%`. They now validate the complete numeric address with Node's IP validator. Tests cover empty and repeated scope delimiters on both backends and retain valid scoped addresses.
4. **Documentation:** README now links to the retained v2.0.1 release execution report rather than the superseded initial failed run.

## Coverage changes

Added a real package-file edit through `PortService.snapshot()` at the TTL boundary, rendered TUI assertions for multiple bindings, duplicate PID/project and malformed PID cases, unknown Windows start-time TTL coverage, and a simulated bounded readiness wait with input/cleanup assertions. Native terminal scenarios now check the selected fixture's actual port. The readiness unit test still simulates the wait and cleanup rather than executing both native harness cleanup paths; Windows cancellation/late-publication and absent-PID cache-pruning cases remain candidates for additional focused coverage.
