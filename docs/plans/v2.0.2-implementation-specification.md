# CLI Ports Tool v2.0.2 implementation specification

Status: Implementation-ready specification; no application changes are made by this document.

Target version: **v2.0.2**, replacing **v2.0.1** as the current application version.

## 1. Scope and implementation sequence

Implement these four improvements in order, verifying each before proceeding:

1. Correct the PTY/ConPTY startup-readiness race.
2. Expose listening addresses and IPv4/IPv6 information.
3. Add filtering options to `ports list`.
4. Bound metadata-cache freshness across the package, service and Windows backend layers.

Then update version metadata and current documentation, run the complete local checks, and obtain the cross-platform evidence described below. The stale README verification statement may be corrected as supporting documentation. Do not reopen accepted v2.0.1 findings or redesign discovery, action handling or terminal infrastructure.

The output compatibility, filter semantics and cache policy below are deliberate requirements, rather than decisions deferred to implementation.

## 2. Problem statement and established findings

The findings below come from inspection of the current v2.0.1 source, tests, workflow and retained release evidence. They do not claim that v2.0.2 behavior has been implemented or executed.

### 2.1 Terminal verification startup race

Both `scripts/unix-pty/cli-stage.mjs` and `scripts/conpty/cli-stage.mjs` wait for the TUI header, read observer records once, then immediately assert that raw mode has been enabled. Rendering the first frame and recording the raw-mode effect are separate events. The macOS failure in release run `42241835709` and its observer sidecar established this observation race; the subsequent unchanged-tag run passed. This is a verification defect, not evidence that production raw-mode setup is broken. An unapplied readiness-wait proposal is retained in the v2.0.1 release evidence.

### 2.2 Listener addresses are discarded

`RawListener` and `PortProcess` contain PID and port but no bind-address information. The Unix backend parses `lsof` table output and discards the address and IP family. The Windows query selects only `LocalPort,OwningProcess`, omitting `LocalAddress`. Both backends aggregate records by PID/port, so information from multiple binds is lost. `PortService.enrichRecord` also explicitly reconstructs the output row and must propagate any new data.

Users consequently cannot distinguish localhost, wildcard and interface-specific binds. A bind address alone does not prove external reachability: firewall policy, routing and IPv6 socket options remain relevant.

### 2.3 Static CLI filtering is absent

`ports list` accepts only `--json`. The TUI has filter modes and substring search, but static output always includes the entire snapshot. Filtering can be implemented after successful discovery without changing backend commands, enrichment or action targeting.

### 2.4 Metadata can remain stale indefinitely

`src/project.ts` caches successful package information by package path without expiry. Independently, `PortService.stableProcessCache` retains cwd, project and framework information by PID for as long as that PID remains visible, bypassing further package lookups. Expiring only the package cache would therefore not fix displayed freshness. The Windows backend carries command-line and executable-path metadata forward by PID without comparing the newly observed process start time.

Service and Windows caches already prune absent PIDs on successful collections. Collection contexts stage cache publication and prevent late work from publishing after cancellation. Preserve these safeguards. Windows cwd remains an inferred directory rather than an OS-reported process cwd.

## 3. Proposed implementation

### 3.1 Bounded terminal readiness wait

In both CLI-stage scripts, keep the existing header wait and then use the existing asynchronous `cli.wait` mechanism to repeatedly reload observer records until a record has `type === 'raw' && actual === true`. Use the existing default bounded wait; do not add a fixed sleep, an unbounded poll or larger global deadlines.

After that wait, retain the assertions for real stdin/stdout TTYs, raw-mode availability, terminal dimensions and the absence of static fallback. Start keyboard interactions only after readiness succeeds. Missing raw readiness must still fail with the named wait diagnostic and trigger existing cleanup. Preserve raw-mode restoration, native keyboard, selected identity, launcher and exit assertions.

No production TUI lifecycle change is required. The historical draft is reference material, not a file to apply blindly or rewrite.

### 3.2 Listener-address representation and collection

Introduce a shared binding value with this shape:

```ts
interface ListenerAddress {
  address: string;
  family: "IPv4" | "IPv6";
}
```

Add `addresses: readonly ListenerAddress[]` to collected listener rows and public internal process rows. Backends must produce a nonempty array for each successfully parsed native listener. Update test factories and fixtures accordingly. Every binding in the array belongs to that row's existing PID and TCP port; the array does not contain a second port field.

Retain **one row per PID/port**. Aggregate distinct address/family pairs, remove duplicates and sort deterministically by family (IPv4 first), then address using ordinal string ordering. Do not collapse different PIDs sharing a port or split one PID/port into multiple selectable rows.

Normalize bracketed IPv6 addresses by removing the enclosing brackets in stored data. Keep numeric addresses rather than performing hostname resolution. Retain IPv6 scope identifiers where supplied. Represent wildcard addresses explicitly as `0.0.0.0` for IPv4 and `::` for IPv6. Infer a Unix `*` wildcard's family from the record's IP type; do not infer family solely from the wildcard text. Keep IPv4-mapped IPv6 addresses classified as IPv6, and do not equate an IPv6 wildcard with proven IPv4 coverage.

Unix: extend the current checked `lsof` parser to capture the record's `IPv4`/`IPv6` type and full numeric listening endpoint, parsing the port from the right rather than splitting all colons. Preserve the existing invocation, exit-status/no-match rules and Linux visibility-warning handling. Cover actual Linux/macOS table forms. An unrecognizable address/family must produce `invalid-output`, rather than silently losing a listener or fabricating a wildcard. A wholesale switch to another discovery tool or output protocol is outside scope; if native evidence establishes that the existing table format cannot meet this contract, record the issue and propose the smallest parser/invocation adjustment before broadening the change.

Windows: add `LocalAddress` to the existing required `Get-NetTCPConnection` projection. Require a valid numeric address string and derive its family using Node's IP validation, accounting for a scope suffix. Preserve PowerShell selection, executable resolution, query/error classification and numeric PID/port validation. Merge bindings into the same PID/port row instead of overwriting earlier records.

Propagate addresses through enrichment, deadline fallback and snapshot publication. Addresses come from required enumeration and must survive failed optional metadata collection. Snapshot address arrays and their entries must not be mutable through published rows.

### 3.3 Address presentation and compatibility

- Add `ports list --addresses`. In table mode it appends a `BINDINGS` column; show comma-separated endpoints, with IPv6 bracketed, such as `127.0.0.1:3000, [::1]:3000`. Do not silently truncate addresses in this opt-in static column.
- Without `--addresses`, preserve the existing static table columns and JSON schema exactly.
- `ports list --json --addresses` adds an `addresses` array with the objects defined above to each existing JSON entry. All existing fields and their meanings remain unchanged. Do not leak internal `cwd` or cache fields. Document that the flag explicitly opts into the extended schema.
- Add a `Bindings:` line to `ports check <port>` details and the TUI selected-row detail pane. Show every binding; allow wrapping in the existing pane rather than widening or redesigning the main TUI table. `check` continues to report its first matching PID/port row.
- Do not change browser URL generation: it remains `http://localhost:PORT`. Do not add address selection or URL routing behavior in this release.
- Describe bind scope factually; do not label a service publicly reachable, safe or unsafe based solely on its address.

### 3.4 Static CLI filter contract

Add these options to **`ports list` only**, usable with table output, `--json` and `--addresses`:

| Option | Meaning |
| --- | --- |
| `--port <port>` | Exact numeric TCP port match, using the existing complete-decimal parser and range 1–65535. |
| `--pid <pid>` | Exact PID match. Accept ASCII decimal digits only, including leading zeros, with range 0–4294967295. PID 0 remains representable because the existing backends accept it. |
| `--project <text>` | Case-insensitive literal substring of the displayed `projectName`. Trim the supplied query and reject empty/whitespace-only queries. No glob or regex interpretation. |

Different options combine with AND. Each option may occur once; reject repeated occurrences rather than silently selecting the last value. Do not support comma lists, ranges, aliases or additional filter modes in this release. Unknown options, missing values and invalid values fail with status 1 before constructing the service or starting discovery. Parse PID with the same whole-string discipline as port: reject signs, whitespace, exponents, suffixes and overflow.

Apply predicates to a successfully collected snapshot and preserve its ordering. A successful zero-match filter returns `[]` in JSON and `No listening TCP ports match the supplied filters.` in table mode, both with status 0. With no filters, preserve the existing empty-result message. Required discovery failure must still exit 1 without successful output; filtering cannot hide a discovery error. Optional enrichment warnings remain on stderr, even if affected rows are filtered out.

Do not change TUI filters/search, `check`, `kill`, or no-argument static fallback semantics. Implement a small pure list-filter helper if useful; do not introduce a general query language or move CLI options into platform backends.

### 3.5 Bounded metadata freshness

Use an internal **30,000 ms TTL**, measured from successful acquisition/publication of the relevant value; use the same policy across persistent metadata layers. Inject or fake time for tests. No new public cache configuration, watchers or cache framework is required.

Required behavior:

1. Bound cached cwd/stable process metadata in `PortService`. Re-query it on the first collection after expiry. Keep pruning absent PIDs after successful enumeration. Memory and uptime remain freshly queried as today.
2. Resolve project context for each PID on every successful enrichment, including when cwd is still cached. Do not reuse project/framework fields indefinitely from the service cache. The package cache may serve a fresh result, but its own TTL must independently control project freshness.
3. In `getPackageContext`, re-run nearest-package discovery and reload successful package data after expiry. Changes to name/dependencies, package removal, a newly nearer package and cwd changes must be reflected by the first successful enrichment after the applicable TTL expires. Do not reset an entry's acquisition time merely because it is read.
4. Bound the module-level package cache to 256 entries. Remove expired entries during cache maintenance and evict the oldest acquired entries when the bound is exceeded. No negative/error result is cached for a full TTL; missing, unreadable or malformed packages retain the current fallback behavior and can recover on the next refresh.
5. In Windows process metadata, retain command-line/executable-path reuse only within TTL. If both old and newly obtained start times are valid and differ, discard the old process's metadata immediately, even within TTL. If identity cannot be established, TTL still applies; do not claim same-PID reuse has been conclusively detected.
6. Expired, invalidated or different-start-time metadata must not be silently resurrected by the deadline fallback path. Return known listener identity/addresses with unavailable metadata defaults and an appropriate optional-enrichment warning if refresh cannot complete. Never replace successful required enumeration with an empty snapshot because metadata failed.
7. Stage additions, replacements and successful invalidations through the existing collection publication mechanism. Aborted/failed collections and late asynchronous completions must not publish cache updates. A subsequent collection must not gain a fresh TTL from an unfinished operation. Coalesce metadata work for the same PID within a collection if necessary to keep multi-port results consistent; do not add another global coordinator.

The freshness guarantee is **refresh on the first successful collection after expiry**, not a promise that screen contents update exactly 30 seconds after an external change. Collection deadlines, refresh cadence, permissions and stale-snapshot handling still apply. This improves metadata freshness; it does not provide atomic process identity or eliminate PID-reuse/signalling races. Windows cwd remains best effort.

## 5. Implementation constraints

- Preserve v2.0.1 PID/port action targeting, selection persistence, validation and guarded stop/escalation outcomes. Address aggregation must not change action identity or first-discovered CLI targeting.
- Preserve required-discovery error classification, genuine empty results, warnings on stderr, stale TUI snapshots, serialized discovery, action priority, 15-second collection budget, cancellation and late-publication protections.
- Preserve launcher arguments, full inherited environment, locale behavior and editor/browser lifetime semantics. Ordinary system commands retain their existing locale behavior. Do not redesign environment handling or Windows executable lookup.
- Keep successful default JSON compatible. Address output is opt-in for `list`; existing unfiltered ordering, command names, TUI shortcuts and default table widths remain unchanged.
- Retain direct argument-array execution. Do not introduce shell interpolation of user filter values or extra subprocesses for filtering.
- No general layout, framework-detection, performance, packaging, dependency or architecture redesign. No `ports doctor`, network scanning or reachability probing.
- Native tests may signal only authenticated owned fixtures under the existing safeguards. If ownership/process identity is unavailable, fail safely and send no signal. Do not terminate unrelated processes or launch real editors/browsers during automated verification.
- Keep historical artifacts unchanged and collect fresh evidence in run/attempt-specific directories. A configured job or fixture test is not proof of native execution.

## 8. Testing and verification requirements

### 8.1 Component regression coverage

**Readiness:** exercise header-before-raw, already-ready and never-ready cases against the actual helper/control flow used by both harnesses. Use deterministic synthetic observations/fake timing where feasible. Assert that input cannot start early, failure is bounded and cleanup still runs. Tests that merely inspect source text or add a sleep are insufficient.

**Addresses:** cover Unix Linux/macOS fixtures for IPv4/IPv6 loopback, wildcard, concrete interface binds and scoped IPv6; Windows `LocalAddress` equivalents; IPv4-mapped IPv6; duplicate descriptors; multiple addresses per PID/port; different PIDs on one port; deterministic ordering; invalid/missing family/address; all existing empty/error cases. Verify address preservation during optional enrichment timeout and immutability of nested snapshot data.

**Output/filtering:** assert the exact default JSON field set and existing default table columns, extended JSON shape, complete bracketed IPv6 endpoints, detail-pane output, and `check` first-match behavior. Cover each filter, AND combinations, casing, query trimming, empty text, duplicate options, PID 0/max/overflow, leading zeros, malformed port/PID strings, unknown options and missing values. Verify invalid input never invokes the service; no matches exit 0; failed discovery exits 1; warnings remain on stderr. Include built-CLI tests, not only predicate tests.

**Caches:** with controlled time and isolated cache state, verify reuse before expiry, refresh exactly at/after expiry, package name/framework edits under a stable PID, package addition/removal/malformed-and-repaired files, cwd changes, TTL on Windows metadata, changed start-time invalidation, unknown start-time limits, absent-PID pruning, expired fallback behavior, 256-entry eviction and cancelled/late writes. Exercise through `PortService.snapshot()` as well as package/backend units so the previous service-cache bypass cannot recur. Do not rely on real 30-second sleeps.

**Preservation:** run all existing action, discovery, launcher environment/lifetime, ownership, selection, timeout/cancellation and terminal-decoder regressions. Extend fixtures to include addresses without weakening their original assertions.
